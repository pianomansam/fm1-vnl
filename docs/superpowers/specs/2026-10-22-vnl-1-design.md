# VNL-1: design

A generative lo-fi hip hop firmware for the M-VAVE FM-1. Status: design, from the brainstorming session of
2026-10-22. Research behind it: `docs/research/` (genre study, measured arrangements of 19 tracks, how other FM-1
firmwares work).

Marking: **(Sam)** = decided by Sam. **(call)** = Claude's call, open to change. Unmarked = follows from those.

## Music knowledge

The musical rules behind this design live in [`docs/music/`](../../music/README.md), split in two: **general
musicianship** that holds in any genre (chord-scales and avoid notes, voice leading, bass lines, rhythm, form,
melody: [general.md](../../music/general.md)) and **lo-fi hip hop and Sam's taste** (tempo, swing, song length,
maps, one loop per song, no substitutions, diatonic bass, dust and bed: [lofi.md](../../music/lofi.md)). Ideas from
other apps not adopted yet: [ideas-from-other-apps.md](../../music/ideas-from-other-apps.md). This spec stays the
design of record; those files track each rule's status and source.

## Intent

VNL-1 turns the FM-1 into an endless lo-fi radio that writes its own songs. Each song is a real, short lo-fi track
with a beginning, a groove, small changes and an ending; then a breath of silence and a new song that is clearly
different from the last. Sam listens to it while studying and coding **(Sam)**, so it must be soothing and never pull
attention: like the ambient firmwares, but in the lo-fi genre.

What makes it special among FM-1 firmwares: AMB-1 and its forks play an endless stream with no form (DUB-1 looks only
one phrase ahead); LOF-1 needs a player. VNL-1 plans whole songs, varies them deliberately song to song, and lets the
listener steer the dice.

The interest is in the **generative sequencing side**: song maps, chords, melody, rhythm, variation **(Sam)**.
Instruments matter as a varied backbone, not as the main effort.

## Goals

1. Songs that sound like the genre: 2–3.5 minutes, 70–90 BPM, swung, one chord loop with rich colors, layers coming
   and going in 4/8-bar blocks.
2. Every song distinct from the previous one, in both sound (instruments, texture) and music (key, tempo, loop,
   groove, map) **(Sam)**.
3. Listener control over the rolls: see them, change them by hand or by dice, at the next phrase boundary.
4. Curated content built with Sam's ears in a browser bench, starting from researched guesses **(Sam)**.
5. Runs on the FM-1 within its CPU, flash and RAM; tested on Sam, then released publicly when Sam is happy **(Sam)**.

## Non-goals (for now)

- MIDI in/out, clock sync: self-contained **(Sam)**.
- Taste learning (saved songs steering future rolls, as MAKU's likes): later, maybe **(call)**.
- Long or complex harmony; key changes inside a song's plan; second progressions as a norm.
- Live-performance features (mutes, solos, DJ effects).
- Audio preview of a roll: preview is on screen only **(Sam)**.

## Anti-goals: failure even if it works

- **Musical clashes** **(Sam)**: wrong notes against the chord, parts colliding in register, timbres that fight.
- **Startling transitions** **(Sam)**: abrupt entries, jumps in loudness, jarring effects. Excluded outright: record
  skips, backspins, stutters, tape-stop endings (none in the measured tracks) **(call)**.

## Constraints

- **Hardware:** FM-1, JieLi AC79 single core, 581 KB flash app slot, 96 KB RAM (.data/.bss), 336 KB buffer pool,
  no external RAM, 240×240 color screen, 4 knobs, keys and buttons, 44.1 kHz stereo.
- **Platform:** fm1-base (MPL-2.0) with felucca-bsp, as already scaffolded in this repo (`app/`, `base/`, identity
  `FM-1_22`, Bluetooth off).
- **Licensing: VNL-1 stays MPL-2.0 (Sam).** Code may come from fm1-base, AMB-1 (MPL), Mutable Dreams (MIT: its
  Plaits and Rings ports) and upstream Mutable Instruments (MIT). DUB-1, LOF-1/HYP-1, MAKU, Tuna, Bunker Evolved,
  Jangada, Mini-Tone and TRIBE are GPL-3.0: **ideas only, no code**; their mechanisms are reimplemented.
- **Audio thread:** sound renders in the audio interrupt; all planning and rolling happen on the main loop and reach
  the engine as commands (AMB-1's model). Float only, no libm (fm1-base's fastmath).

## The song

### The roll

Starting a song rolls a set of choices from a seed. A song is fully reproducible from its seed plus any changes made
to it. Each choice can be **picked by hand or re-rolled with dice**, both in the firmware and in the bench **(Sam)**.

| Choice | Range / source |
| --- | --- |
| Length | 2–3.5 min, usually ~2.5 (≈40–64 bars) **(Sam: "what makes sense for lo-fi")** |
| Tempo | 70–90 BPM (research: median 85) |
| Key and mode | any key; mode follows Mood |
| Mood | sad ↔ happy **(Sam)**; steers mode (minor/Dorian ↔ major/Lydian), chord colors, register, ear candy |
| Motion | how much the arrangement moves **(Sam)**: how many layer moves the map's dice make |
| Swing, lateness | swing ~52–62%; snare 10–30 ms late, hats up to ~70 ms late (research) |
| Song map | from the map library |
| Chord loop | from the progression library, transposed; color (7ths vs 9ths/13ths) and voicing rolled |
| Instrument set | from the curated set library **(Sam: curated sets, not free mixing)** |
| Drum pattern family | from the pattern library (boom-bap, half-time, sparse…) |
| Lead motif | generated per song (below) |
| Dust | amount + flavor (warm vinyl-style / wobbly tape-style) |
| Surface noise | vinyl crackle, tape hiss, or none |
| Ambience | rain, or none (more later) |

**Novelty rule:** a new roll must differ from the previous song in at least half of the main choices (map, loop, set,
pattern family, mode, dust/noise/ambience, tempo by ≥ 6 BPM) **(call; research: Hamming-distance rule)**. Dice on a
single choice never return the current value.

### Song maps

A curated library of **skeletons** **(Sam)**: each fixes the big moments (how the song enters, its middle event, how it
leaves); the smaller moves inside 8-bar blocks roll with Motion, so a map never plays the same way twice **(Sam)**.
Seed maps, from shapes measured in real tracks (`docs/research/lofi-audio-arrangements.md` §4, §7;
`lofi-midi-arrangements.md`), as proposed in the brainstorm:

| Map | Skeleton |
| --- | --- |
| Classic | 4-bar keys intro → drums + bass together → hats join later → one 4-bar drum break (43–65% through) → drums leave, keys outro |
| Slow bloom | 8-bar intro → snare + hats only (no kick) for 8 bars → kick + bass arrive → drums never drop → long fade |
| Straight in | 0–1 bar of bed → full groove from bar 1 → only small hat drop-outs → drums to the end, quick ring-out |
| Breather | standard entry → a long middle block (8 bars) with kick + bass out, snare + hats carrying → full return → keys outro |
| Drift | sparse throughout: drums come and go, keys and lead carry most of it; the sleepiest map |

**Section names** (for the screen's progress strip and the map data) **(call):** intro, groove, lead (a groove block
where the lead plays), break (drums out or thinned), outro. They describe which roles play, not new harmony: the loop
never changes (the mockup's "A/B" labels become these).

The measured norms every map works within:
- Intro: bed alone at most 1–3 bars, then keys alone, filtered/darker, ~4 bars (0–8).
- Drums and bass enter together on a 4-bar boundary; hats/shaker often join 4–8 bars later.
- Middle: 8-bar blocks; moves are layer drop-outs (hats out 4–8 bars; kick and bass out ~8 bars with snare/hats
  carrying; one 4–8 bar drum break, usually 43–65% of the way through, keys/bass/lead carrying it; 1-bar drum drops
  on the last bar of an 8-bar phrase). ~40% of tracks never drop the drums.
- Drums: snare on 2 and 4 (or half-time on 3), kick on 1 plus 1–3 offbeat hits, hats in 8ths at about half the
  kick/snare velocity; swing light, median 54–56%, never past ~70%.
- Outro: drums often leave ~4–10 bars before the end, keys alone mirror the intro; ring out (most) or fade.
- Steady state: drums + bass + keys.
- Every change on a 4/8-bar boundary; at most 1–2 roles move per boundary; parts fade or filter in and out.

### The band: six roles **(Sam: chords the star, lead a guest)**

| Role | Plays | Presence |
| --- | --- | --- |
| Chords | the loop, 4-note jazz voicings (C3–E4 area), rolled not struck; style rolled: held, stabs, offbeats, arpeggio | nearly always |
| Drums | swung boom-bap family pattern, ghost notes, late snare, fills only at boundaries | per map |
| Bass | roots/fifths locked to the kick, sometimes walking | with the drums |
| Lead | the song's motif and its development | some blocks only |
| Ear candy | a few notes, answers, swells at transitions | occasional, never over the lead |
| Bed | surface noise + ambience | steady, the one constant |

Register bands per role keep parts apart; lead and ear candy take turns.

### Harmony **(Sam)**

One chord loop per song, 2–4 chords, looping every 2–4 bars; nothing long or complex. A rare second loop is allowed
as an option **(call)**. The library is curated: classic lo-fi shapes as roman numerals (ii–V vamps, IV–iii–ii–I, the
"royal road" IV–V–iii–vi…), tagged vamp / loop / jazzy (one twist chord at most), plus Sam's own. Starting mix
roughly 40 / 45 / 15 **(call)**. Richness comes from chord colors and voicings; intro/outro use a darker voicing.

### Melody **(Sam: fully generated)**

Per song, one 1–2 bar motif is generated from rhythm cells and the chords' guide tones (3rds, 7ths), pentatonic-
leaning, sparse (about a third of beats), notes slightly late. It is developed across the song as a composer would
(after Tuna's approach, reimplemented): stated, moved onto the next chord with the same shape, given a new ending,
restated. Repetition dominates, as in real tracks: of 4-bar lead phrases, about half restate an earlier one exactly,
~15% are variants, the rest new (measured, `lofi-midi-arrangements.md`). Strong beats land on chord tones; avoid notes are avoided. Ear candy may answer the lead's phrases.

## Sound

**Synthesis first (Sam):** synthesized voices are more flexible than samples, and the lo-fi chain forgives a lot.
More Mutable Instruments ports are welcome if they fit CPU and memory **(Sam)**.

### Voices and their fallback ladders **(Sam: have backups)**

| Role | First choice | Fallback | Last resort |
| --- | --- | --- | --- |
| Chords | Plaits FM (via Mutable Dreams' port) | AMB-1's FM Rhodes (proven on the FM-1) | small CC0 samples, 16 kHz ADPCM (LOF-1's approach) |
| Drums | Plaits analog kick/snare/hat | simple hand-built synthesis | small sampled kit (~50–100 KB, 12-bit) |
| Bass | Rings / Karplus–Strong pluck | sine + sub, soft envelope | samples |
| Lead, ear candy | Rings modal (kalimba, vibes, bells) | 2-op FM bells (AMB-1's) | samples |
| Bed, dust | synthesized noise and filters | (already cheapest) | |

Each role has a CPU budget, measured on the real FM-1 early; the set roller never picks an over-budget combination;
a lighter mode (fewer resonator modes, half-rate voices) is the safety valve, as in Mutable Dreams **(call)**. Rungs
are chosen per role independently.

### The lo-fi chain and the bed **(Sam: three independent layers)**

- **Dust** (coloring the music): low-pass (~1–5 kHz), wow and flutter, soft saturation, bit/sample-rate grit, light
  kick ducking; an amount and a flavor (warm vinyl / wobbly tape).
- **Surface noise:** vinyl (sparse random clicks, faint hiss, a slightly louder tick per 1.8 s rotation) or tape hiss,
  or none. Synthesized.
- **Ambience:** rain (low-passed noise wash, droplet ticks, slow gusts) or none. Synthesized.
- Curated pairing rules keep them from getting muddy. The bed stays steady through sections; it opens and closes the
  song. Levels steady across sections and songs.

## Ideas from neighboring genres **(Sam: innovate, stay true to lo-fi; split approved)**

Filtered through the anti-goals. Excluded: EDM drops and risers, dub throws, trap hat rolls, abrupt beat switches.

- **First version (data or small rules):** lo-fi bossa, city pop, neo-soul and chillwave flavors as library entries;
  a brushes-and-ride drum family; reharmonize on repeat (a richer color on one chord of a later pass of the loop;
  **no substitutions and no tritone subs anywhere, Sam, after listening**); head–solos–head as the melody plan; trading fours between lead and ear candy; slow automation arcs on
  filter, wobble and reverb over 16–32 bars (scaled by Motion); evolving weather (rain builds and passes); a pedal-
  tone bass style; a gentle one-bar noise swell before the drums enter; brief polymeter (a 3-against-4 shaker);
  **DJ key flow**: the next song rolls into a related key (circle-of-fifths/relative neighbor) and a nearby tempo,
  while the novelty rule still forces the other choices to change.
- **Soon after:** unequal-loop ear candy (AMB-1's logic on the 4-bar grid); a reverb freeze tail at the end; kit swaps
  for one block; synthesized vocal chops (AMB-1's formant voice).
- **Later, its own feature:** **self-sampling chops**: VNL-1 records its own loop into a ~256 KB buffer and plays it
  back chopped, re-ordered or pitch-shifted in a later block (the MPC move). The most distinctive idea; it competes
  with reverb/delay for the pool, so it's a version-2 headline.

## Playing it

### Transport **(Sam)**

- Power on or PLAY after stop: a fresh roll, unless a previewed or saved song was chosen.
- A song ends with its map's ending, then **true silence** of ~2–4 s, then the next song; the screen shows the next
  song's card during the gap.

### Steering **(Sam)**

- The home screen shows the rolls; the four knobs are **Key, Tempo, Motion, Mood**; other rolls (set, map, loop,
  pattern, dust, noise, ambience) on further pages **(call: grouping)**.
- Every roll can be set by hand or re-rolled by dice. Changes apply to **the current song only**, at the next phrase
  boundary (4 or 8 bars), shown as a countdown ("TEMPO 78 IN 3 BARS").
- How changes land **(call)**: key moves the whole band, motif keeps its shape; tempo glides over a bar or two; mood
  re-rolls the loop toward the mood; instruments crossfade at the boundary.
- **Universal re-roller** while stopped: each press rolls a whole song and shows it (screen F); knobs tweak it; PLAY
  starts it.

### Saving **(Sam)**

Save the playing song as it stands (seed + changes, a few dozen bytes) to a list of 16–32 slots **(call)**, shown with
title, key, tempo, mood. Saving stores the song's **final state** (seed + the choices as they stand), and replay
plays that state from the first bar: a key changed at bar 30 applies from bar 1 **(call)**. Flash writes only on save.
**Exactness (call):** replay is exact within one firmware version. Across updates, stored choices refer to library
entries by stable ids (MAKU's rule), so a saved song comes back as recognizably the same song, but generator and
library changes may alter details; no generator versioning or frozen draw order.

### Screens **(Sam: D and F)**

The frame FM-1 owners know from AMB-family firmwares: header (chip, key, tempo), a centerpiece, four knob gauges along
the bottom with the page name and dots above them.
- **D, now playing:** song number, key/mode, tempo; generated title; instrument set and bed in one line; the current
  chord large with the loop under it; pending-change countdown; a progress strip cut into the map's sections; knobs.
- **F, preview (stopped):** the rolled song in full (title, length, band, drums, chords, bed), "roll again / play
  this", the knobs to tweak.
Mockups: `docs/superpowers/specs/mockups/now-playing-v2.html` (D and F; a fragment, styled by the brainstorm companion). Generated song titles **(call)**.

## Building it

### The curation bench **(Sam)**

A browser page running the real engine (the emulator build). Sam rolls songs, listens, sees every choice, picks or
re-rolls any of them, auditions one piece alone (a loop with a set, a pattern, a map), tweaks values, and rates
entries keep / fix / drop. Results save to readable data files in the repo (instrument sets, progressions, drum
patterns, song maps, mood mappings, pairing rules); a script generates the firmware's tables from them, as Mutable
Dreams does **(call: mechanism)**. Libraries start from researched guesses, each noting its source **(Sam)**.

### Order **(call)**

1. The generator first (roll, maps, harmony, rhythm, melody, novelty), heard through simple placeholder voices in the
   host simulator and the bench.
2. A short hardware spike: install on the FM-1, measure each candidate voice's CPU, settle each role's rung.
   **Who runs hardware steps:** Sam, with minimal effort. Following Mutable Dreams' bench (made small): the test
   firmware shows CPU (`plat_cpu_pct`) on a dev page, and a bench script over USB-MIDI steps through candidate voices
   and combinations, reads CPU load and dropouts (and the FM-1's USB audio for clipping/silence), and writes a JSON
   report. Sam plugs in, runs one install and one bench command, and shares the report **(Sam: follow other
   firmwares; mechanism is the call)**.
3. Voices and the lo-fi chain; curation rounds with Sam.
4. Screens, controls, saving; then the manual, site and installer (fm1-base provides them) for release.

### Testing

- Host simulator scenarios (fm1-base's): a song plays start to end, changes land on boundaries, saved songs replay
  exactly, novelty holds over many rolls.
- Automatic clash checks over many rolled songs: lead/ear-candy notes against the chord, register collisions, level
  jumps between sections and songs.
- CPU measured on the device for the heaviest rolled combinations.

## Left to the builder

Exact probabilities inside maps and Motion's scaling; rhythm-cell and pattern details; the data file format; voice
parameters; page layout beyond D and F; button mapping for dice, save and the slot list; title generation; how many
saved slots; the CPU budget numbers.

## Later, maybe

Saved songs steering future rolls (MAKU-style likes with mutation); MIDI out; more ambiences (room tone, city);
more Mutable ports; a second loop as a regular option if songs feel too static.
