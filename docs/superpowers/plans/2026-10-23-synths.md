# Synths Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add synth instruments for every role (vintage analog, 80s FM/digital, chiptune) and sets that use them.

**Architecture:**
- Two new voice models in `app/engine/voices.c`:
  - **M_SUB:** one oscillator, a sub-octave and noise, a low-pass with its own envelope, mono/glide.
  - **M_CHIP:** a pulse, a stepped triangle and noise.
- The FM sounds are new patches on the existing M_EP, M_BASS and M_BELL models.
- New `INS_*` entries and about six new sets in `app/song/library.c`. The roll picks them like any other set.

**Tech Stack:** C99, float only (single-precision FPU), no libm (fm1-base fastmath), no malloc. Run the tests with
`PATH=$PWD/.venv/bin:$PATH sh tests/run_tests.sh`, cost with `tools/cost-bench.sh`, memory with `tools/mem-check.sh`.

**Spec:** `docs/superpowers/specs/2026-10-23-synths-design.md`, including its "Calls made for the builder".

## Global Constraints

- Engine rules: C99, float only, no libm, no malloc, ISR-safe, deterministic per seed (noise seeded per song in
  `voices_clear`), every decaying or recirculating state flushed and listed in `vx_tiny`.
- **CPU:** host ratio ≤ 1.0, judged on `sh tools/cost-bench.sh --forced 7 20 49 100 128 183` and the no-arg picker.
  Record each new patch's `--parts` row in docs/cost.md (Sam's standing rule: track the cost of everything).
- **Memory:** image ≤ 409600 B, RAM .data+.bss ≤ 81920 B, pool ≤ 307200 B (`sh tools/mem-check.sh`).
- **Music rules stay:** no rubs, rootless voicing, registers, the lead-over-keys rule (the lead 4–6 dB above the keys
  while it plays, with the keys ducking under it; from the level fix on this branch).
- **Warm by default:** synths low-passed. The dust still colors them.

## Review Focus

1. **Glide across a steal or a rest.** A mono lead must glide only from a held note. A note after a rest starts
   clean; a steal still fades over 4 ms. Test in Task 2.
2. **Resonance blow-up.** The Moog bass's 4-pole filter at high resonance, swept by its envelope, must stay bounded
   (no NaN, peak < 1.0) at every note in the bass range. Test in Task 2.
3. **Chip aliasing at the top.** Chip voices run at full rate with hard edges. High chip-lead notes (to MIDI 88) must
   not alias audibly into the band below 4 kHz. A band-energy check in Task 1.
4. **Existing seeds change sets.** Adding sets redraws sets for some seeds. The roll tests and the renders must use the
   new draw; nothing may assume a seed's old set. Task 4.
5. **Over budget with a synth set.** A Juno set with dense comping, rain and dust 3 is a new candidate for the
   heaviest roll. The bench list must include it. Task 5.

### Task 1: Wider patches and the chip model (M_CHIP)

**Files:** Modify `app/engine/patch.h`, `app/engine/patch.c`, `app/engine/voices.c`, `app/song/library.h/.c`;
Test: `tests/host/song_test.c`

**Interfaces:**
- Produces:
  - `vx_patch_t.p[16]` (was 8). Every existing patch keeps its values in the first 8 slots.
  - `M_CHIP` in the model enum.
  - New instruments: `INS_CHIP_CHORDS`, `INS_CHIP_LEAD`, `INS_CHIP_BASS`, `INS_CHIP_BLIP`, added before `INS_NONE`.
  - The patch p[] layout for M_CHIP, documented in patch.c: wave (pulse/triangle/noise), duty (0.125/0.25/0.5),
    vibrato rate and depth, arpeggio off.

- [ ] **Step 1: Write the failing tests:**
  - `test_vx_patches` (existing) covers the new INS entries automatically: peak, NaN, release to silence,
    determinism.
  - `test_chip`:
    - The pulse at duty 0.25 has its 4th harmonic missing (< −30 dB against the fundamental).
    - The triangle is stepped to 16 levels (count the distinct sample values in one cycle at low pitch: 15–17).
    - The chip lead's pitch sits exactly on the semitone between vibrato swings: the median frequency within
      ±3 cents.
    - At MIDI 88, energy below 4 kHz that isn't a harmonic is < −40 dB against the fundamental (Review Focus 3).
- [ ] **Step 2: Run them to see them fail** (`INS_CHIP_*` undefined).
- [ ] **Step 3: Implement**
  - Widen p[].
  - Implement M_CHIP: polyBLEP-free hard pulse with a band-limited edge (a 1-sample minBLEP-style correction is
    enough), the stepped triangle, and noise from the voice's seeded noise.
  - Add the four INS and their patches. Chip chords go in the chords role, the lead in the lead role, the bass in the
    bass role, blips in the candy role.
  - `lib_ins_sustained`: chip chords sustained; chip lead and blips percussive.
- [ ] **Step 4: Run all tests; all pass.** Record `--parts` rows for the chip patches.
- [ ] **Step 5: Commit:** `feat(engine): wider patches and a chiptune voice`

### Task 2: The subtractive model (M_SUB) with mono glide

**Files:** Modify `app/engine/voices.c`, `app/engine/patch.c`, `app/song/library.h/.c`; Test: `tests/host/song_test.c`

**Interfaces:**
- Produces:
  - `M_SUB`, with its p[] layout documented in patch.c: wave (saw, pulse, sine, triangle), pulse width, sub level,
    noise level, cutoff, resonance, key tracking, filter-envelope amount/attack/decay, 4-pole flag, mono flag,
    glide ms.
  - New instruments: `INS_JUNO`, `INS_ORGAN`, `INS_MOOG_BASS`, `INS_SAW_LEAD`, `INS_SQUARE_LEAD`, `INS_SINE_LEAD`,
    `INS_SYNTH_PLUCK`.

- [ ] **Step 1: Write the failing tests** `test_sub`:
  - The filter envelope sweeps: the spectral centroid at 20 ms is ≥ 2× its value at 400 ms, for the Moog bass and the
    synth pluck.
  - The 4-pole slope: at a fixed cutoff, a saw's harmonic two octaves above the cutoff is ≥ 18 dB below the 2-pole
    version.
  - **Glide (Review Focus 1):**
    - A saw lead's legato note reaches its target pitch within the patch's glide time ±20%, monotonically.
    - A note after a rest starts on pitch, with no glide.
    - A stolen voice still fades within 5 ms.
  - **Sine lead:** delayed vibrato, none before 250 ms and ≥ 4 cents after, as the winds' test does.
  - **Resonance (Review Focus 2):** the Moog bass at maximum resonance, swept, at every note 28–55: no NaN, peak
    < 1.0.
  - **Half-rate rule:** patches whose highest cutoff with envelope stays ≤ 8 kHz render half-rate on the chords role.
    The equivalence test from Task 7c (band ≤ 8 kHz within 1 dB) covers the Juno and the organ.
- [ ] **Step 2: Run them to see them fail.**
- [ ] **Step 3: Implement**
  - M_SUB, frugal like the Juno-106: one polyBLEP oscillator, sub and noise, a 2-pole TPT SVF (4-pole for the Moog
    bass: two cascaded SVFs with shared resonance feedback, clamped), and coefficients at control rate.
  - Mono and glide in `pool_on`: the bass role's legato rule, extended to lead patches with the mono flag.
  - The seven INS and their patches, all warm (cutoff low by default). The Juno patch's chorus amount sits at the
    Juno depth.
  - `lib_ins_sustained`: Juno, organ, and the saw, square and sine leads sustained; the synth pluck percussive.
- [ ] **Step 4: Run all tests; all pass.** Record the `--parts` rows. Keep the forced max ≤ 1.0. If a patch is over
  budget, lower its rate or features before cutting voices.
- [ ] **Step 5: Commit:** `feat(engine): a subtractive voice with glide: Juno, organ, Moog bass, synth leads, pluck`
