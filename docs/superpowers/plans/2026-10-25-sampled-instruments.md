# Sampled Instruments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring Sam's spike picks into the engine as new options: the Knight piano, the FreePats nylon (replacing the
synth nylon), the Emilyguitar, a strum engine, the string synth as a high and a cello lead, five sampled kits with
choke and a shared ride, and stab comping on the sampled instruments.

**Architecture:** One ADPCM sampler model (M_SAMP) plays every sampled pitched instrument; sample data is generated by
a packer from fetched CC0 sources and committed as a C table. A strum comping style on the song side emits per-string
events. A second new model (M_STR) ports the spike's string-section synth. Sampled kits are a drum path beside the
synth kits, chosen per song from the set's pair, with a per-song ride roll.

**Tech Stack:** C99 (engine, host tests), Python 3 with numpy/scipy (packer only, build time), the existing host test
harness (`tests/host/song_test.c`).

**Spec:** `docs/superpowers/specs/2026-10-25-sampled-instruments-design.md`. Reference code: branch
`spike/instruments` (read with `git show spike/instruments:<path>`; never check it out in the main tree), its doc
`docs/research/instrument-spike-2026-10-24.md`, and `docs/research/cpu-vs-flash-2026-10-25.md`.

## Global Constraints

- C99, float only, no libm, no malloc, ISR-safe, deterministic per seed, denormal-safe (`vx_tiny()` stays 0).
- Add, don't replace: every synth instrument, kit and set stays. Only the synth (Karplus-Strong) nylon is replaced.
- Reuse: one sampler voice, one strum engine, one string synth (two patches), one drum sample pool, one shared ride.
- Never use a part Sam removed: the upright bass, offbeat-only comping (CS_OFFBEATS), Swirly, raw cross-sticks (the
  warm kit's processed sidestick is approved), the Kawai, the FluidR3 cello, shakers other than the VCSL small one.
- Licenses CC0 or MIT only, verified at the source; every source in `CREDITS.md` (license, URL, attribution). No GPL.
- Samples: 16 kHz mono 4-bit IMA ADPCM, attack plus crossfaded loop (cymbals may use a higher rate: Task 7's A/B).
- Budgets: CPU ≤ 0.97 (`sh tools/cost-bench.sh --forced 20 7 155 138 100 22` plus the re-picked heaviest roll);
  flash within the image budget (`sh tools/mem-check.sh` prints `mem-check: ok`); results in `docs/cost.md`.
- Mix: the existing level tests pass with every new set (lead 8-10 dB over the keys; pads; duck 2-4 dB).
- Music rules: rootless pianist voicings for keys, no semitone rubs, no substitutions, registers as today.
- New seed streams: 192 (kit pick), 193 (ride roll), 194 (strum pattern and speed). Used today: 100-191.
- Tests: `PATH=$PWD/.venv/bin:$PATH sh tests/run_tests.sh` (all green, -Werror); a single test after a build:
  `app/build/tests/song_test <substring>`.
- Every task that changes sound ends with renders (`./new-song.sh SEED`, with and without `BED=0`) and their WAV
  links, for Sam's ear. Commit trailers as in the repo's history; never push or merge.

## Review Focus

1. **A song after a song:** a sampled or strummed song leaves no state behind (sampler positions, choke, ride
   section); a seed renders the same alone or after another. Test in Task 2 (sampler) and Task 8 (kits, ride).
2. **Notes outside the sampled range** (a low voicing, a high lead): the nearest zone plays at the right pitch, never
   reading past a table. Test in Task 2.
3. **A stolen sampler voice mid-loop:** it fades (about 4 ms, as every steal), no click. Test in Task 2.
4. **A mid-song reconfigure** (`vx_reconfigures`) from a synth kit to a sampled one, or a set change: sounding hits
   and notes finish on what they started with; nothing reads a freed or wrong table. Test in Task 7.
5. **Velocity extremes** (1 and 127) on sampled notes and hits through the drive: no NaN, no denormals, peaks within
   today's limits. Test in Task 7 (drums) and Task 2 (notes).

### Task 1: The sample pipeline and data

**Files:** Create `tools/samples/{fetch.sh,pack.py,sf2.py,manifest.json}`, `app/engine/samples.h`,
`app/engine/samples_data.c`. Modify `CREDITS.md`. Test: `tests/host/song_test.c`.

**Interfaces:**
- Produces (`samples.h`):
  ```c
  typedef struct { const uint8_t *data; uint32_t len, loop_start, loop_len; uint16_t rate; uint8_t root;
                   float gain; } smp_zone_t;   /* ADPCM nibbles; loop_len 0 = one-shot */
  typedef struct { const smp_zone_t *z; uint8_t n; } smp_bank_t;  /* zones sorted by root */
  enum { SB_KNIGHT, SB_NYLON, SB_EMILY, SB_N };
  enum { SH_GG_KICK, SH_BR_KICK, SH_GG_SIDE, SH_GG_SNARE, SH_FS_POPLAR, SH_VC_ROPE, SH_GG_HAT, SH_GG_OHAT,
         SH_BR_CHICK, SH_BR_OHAT, SH_VC_PEDAL, SH_VC_HAT, SH_VC_OHAT, SH_VC_SHAKER, SH_RIDE, SH_N };
  const smp_bank_t *smp_bank(int id);   /* NULL out of range */
  const smp_zone_t *smp_hit(int id);    /* NULL out of range */
  uint32_t smp_bytes(void);             /* total sample data, for mem-check and the test */
  ```
- Bank contents: Knight 6 zones (VCSL, CC0); FreePats Spanish Classical nylon 7 zones at 0.5 s; Emilyguitar 8 zones
  (E2 A2 Eb3 A3 Eb4 A4 Eb5 A5, `mf`). Hits as in the spec's kits table, plus the VCSL small shaker (high-passed
  400 Hz in the packer) and the Big Rusty 22" ride; open hats about 0.4 s, the ride about 0.5 s. Source paths,
  velocity layers and trims: the spike doc's tables (Rounds 1-5).

- [ ] **Step 1: Write the failing test** `test_samples_table`: for every bank and hit, `len > 0`, zones strictly
  ascending by `root`, `loop_start + loop_len <= len`, `rate` in {16000, 22050, 32000}, `gain > 0`; the sum of all
  zone byte sizes equals `smp_bytes()`; `smp_bytes() <= 200 * 1024`.
- [ ] **Step 2: Run it, expect a compile failure** (no `samples.h`).
- [ ] **Step 3: Port the packer** (spike `pack.py` + `pack2.py` into one `pack.py` reading `manifest.json`, writing

### Task 2: The sampler model (M_SAMP), the Knight, the nylon and the Emilyguitar patches

**Files:** Create `app/engine/sampler.c/.h`. Modify `patch.h/.c` (M_SAMP; INS_KNIGHT, INS_EMILY), `voices.c`
(dispatch, voice struct member, half rate), `library.h` (enum). Test: `song_test.c`.

**Interfaces:**
- Consumes: Task 1's `smp_bank`.
- Produces: `M_SAMP` appended before `M_N`; `INS_KNIGHT`, `INS_EMILY` appended before `INS_NONE`; `INS_NYLON` keeps
  its id but becomes an M_SAMP patch (the KS nylon removed from the table; M_PLUCK stays for the guitar lick).
  M_SAMP's `p[]`: p[0] bank id (SB_*), p[1] the tone's one-pole cutoff in Hz at full velocity, p[2] velocity to tone
  (0-1), p[3] 1 for a muted note (the strum's chuck: short, dark), p[4] vibrato cents (0 off).
  ```c
  void samp_start(smp_voice_t *v, const vx_patch_t *p, float note, float vel);  /* sampler.h */
  float samp_sample(smp_voice_t *v);   /* one sample at the voice's rate; 0 when done */
  void samp_release(smp_voice_t *v);
  ```

- [ ] **Step 1: Write the failing tests** `test_samp`:
  - pitch: notes 40, 52, 59, 64, 71, 76, 83 (zone centers and boundaries) on each bank render within 3 cents of
    `mtof(note)` (autocorrelation over 200 ms after the attack);
  - out of range: notes 20 and 110 play the nearest zone (no read past `len`, checked by a guard build flag or by
    the rendered pitch) and stay finite;
  - loop: no sample-to-sample jump above 0.05 full scale after the attack, across 3 s of a held note;
  - release: after `samp_release` the level falls monotonically (per 64-sample RMS) to under -60 dB, never stepping
    by more than 6 dB between blocks;
  - steal: a 5th note on a 4-voice pool fades the victim in under 6 ms, no jump above 0.05;
  - velocity 1 and 127: finite, `vx_tiny() == 0`;
  - carryover: seed 2 renders bit-identically alone and after a song on a Knight set (Task 5 adds the sets; until
    then, assign INS_KNIGHT with `vx_assign` in the test).
