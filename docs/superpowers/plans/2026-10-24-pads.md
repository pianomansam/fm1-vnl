# Background Pads and Strings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A quiet background layer on a new role: a sustained mid-range chord over percussive keys, and a high solo
note (one a bar, near the tonic) that comes and goes by section.

**Architecture:**
- **Engine (`app/engine`):** a new pitched role `V_PAD` on its own bus, with a frugal ensemble voice model `M_ENS` and
  two patches (strings and a warm synth pad).
- **Song engine (`app/song/pads.c`):** a pure planner for the chord part and the solo note. `song.c` emits its events
  after the lead plans its bar.
- **Sets:** each set names its pad instrument.

**Tech Stack:** C99, float only, no libm, no malloc. Host tests: `PATH=$PWD/.venv/bin:$PATH sh tests/run_tests.sh`
(`-Werror`). Cost: `sh tools/cost-bench.sh`. Memory: `sh tools/mem-check.sh`. Renders: `./new-song.sh`.

**Spec:** `docs/superpowers/specs/2026-10-24-pads-design.md`, including its "Calls made for the builder".

## Global Constraints

- **Engine rules:** ISR-safe, deterministic per seed, denormal-safe (`fm_flush`, `vx_tiny`).
- **Purity:** the song engine stays a pure function of roll and plan. New per-song choices come from new seed streams
  (use 190–199; check `rng_seed` callers first).
- **Music rules (spec):**
  - no semitone rubs with the keys or bass (the chord part also avoids the lead's notes of the bar)
  - no avoid notes
  - chord part clamped to G3–C5 (MIDI 55–72)
  - solo note clamped to C5–C6 (MIDI 72–84), at least a 3rd above the chord part's top note in the same bar
- **Budget:** ratio ≤ 0.97 on the standard list (`--forced 20 7 155 138 100 22`) and on the heaviest roll re-picked
  after the layer lands. Hard limit 1.0; keep 0.03 for bench noise. If it doesn't fit, cut in the spec's order:
  1. the solo note shares the ensemble voice
  2. quarter rate where the low-pass allows
  3. the chord part drops to 2 notes

  If that still doesn't fit, stop and report. Memory within mem-check's budgets.
- **Levels:**
  - The chord part sits 4–8 dB under the keys where both play.
  - The lead-over-keys test (per-set mean 4–6.5 dB, median 4–6, every song ≥ 2 dB) keeps passing with the layer
    present.
- **The solo note ignores the lead (Sam, for now).**

## Review Focus

1. **The enum shift.** Inserting `V_PAD` renumbers the drum voices (`V_KICK`…), the plan-move buses (`PM_*`), and every
   array sized `V_CANDY + 1` or `V_N`. Nothing may index past or alias a role. Task 1 test: every role and drum
   voice's events still reach their own bus (solo each bus; a kick lands only on the drums' bus, a pad note only on
   the pad bus).
2. **A key change mid-section.** The solo note's voice leading resets to the new key's tonic set, with no held note
   out of key. Task 2 test: a key request landing mid-section never leaves a sounding solo note outside the new key.
3. **A one-chord progression or bars_per_chord 2.** The chord part holds across bars without restriking, and the solo
   note ties. Task 2 test, over progressions with `bars_per_chord` 1 and 2.
4. **Sustained-keys sets.** There is no chord part, only the solo note, and no stray pad voices. Task 2 test.
5. **The song's end and the next song.** The pad releases at the end, and the carryover test (a song renders the same
   alone or after another) holds with a pad set in its pairs. Task 3.

### Task 2: The pad planner and its events (song)

**Files:**
- Create: `app/song/pads.h`, `app/song/pads.c`
- Modify: `app/song/song.c` (emission after `lead_plan_bar`), `app/song/song.h` if `song_t` holds pad state
- Test: `tests/host/song_test.c`

**Interfaces:**
- **Consumes:** `V_PAD` and `lib_set_t.pad` (Task 1); `harmony_voicing_at`, `harmony_chord_at`, `lead_state_t.on/len`,
  `legal()`-equivalent rules (theory.c / harmony.c).
- **Produces:**
  - `int pads_section_in(const song_roll_t *r, int block, int section);`
    - Returns whether the solo note plays in this plan block: 1 in, 0 out.
    - Seeded (stream 190) from the song's seed and the block index.
    - Shares: groove 60%, intro 50%, break 50%, outro 50%, lead 30%.
  - `int pads_chord(const song_roll_t *r, const int keys[4], const int *pcs, int np, unsigned bass_pc, const int *lead_notes, int nlead, const int prev[3], int out[3]);`
    - Returns 2 or 3 notes for the chord: guide tones first (3rd and 7th), then the 5th or the 9th.
    - Within MIDI 55–72, voice-led from `prev`: common tones held, the rest to the nearest legal tone, the top voice
      smoothest.
    - Never a semitone from a keys, bass or lead note.
  - `int pads_solo(const song_roll_t *r, int key, int mode, const int *pcs, int np, const int keys[4], int chord_top, int prev);`
    - Returns the bar's solo note (0: none legal), from scale degrees 1, 2, 3 and 7 within MIDI 72–84, at least
      3 semitones above `chord_top`.
    - Keeps `prev` if it is legal.
    - Otherwise the smallest legal move, ties broken in the order tonic, 3rd, 2nd, 7th.
    - No rubs with the keys or bass.
  - Emission in `song.c` at step 0:
    - Chord part: at each chord change, over percussive keys only (`!lib_ins_sustained(set->chords)`). Length =
      `bars_per_chord` bars; attack and release from the patch.
    - Solo note: each bar of an "in" section. Length runs to the end of the run of bars that keep the same note
      (a tie: no restrike).
    - The layer follows `L_KEYS`: it plays wherever the keys do.

- [ ] **Step 1: Write failing tests** (over 500 rolled songs played through `song_tick`, recording `V_PAD` events):
  - `test_pad_chord`:
    - Present in every bar with keys over percussive keys, absent over sustained keys (Review Focus 4).
    - 3 notes in ≥ 80% of chords, never < 2.
    - Onsets only at chord changes (Review Focus 3).
    - Top-voice motion ≤ 2 semitones in ≥ 80% of changes.
    - Range 55–72.
    - No note a semitone from a sounding keys, bass or lead note.
  - `test_pad_solo`:
    - At most one onset a bar, on step 0, sounding to the bar's end or tied.
    - Scale degree 1, 2, 3 or 7 in 100% of notes, the tonic in ≥ 35%.
    - A common tone is kept across a chord change whenever it is legal; otherwise it moves ≤ 2 semitones in ≥ 90%.
    - Range 72–84, ≥ 3 semitones above the chord part's top.
    - No rubs with the keys or bass.
    - A key request mid-section leaves no sounding solo note outside the new key (Review Focus 2).
  - `test_pad_sections`:
    - Each section kind is "in" within ±10% of its share.
    - A block is all in or all out.
  - Determinism: the same seed gives the same pad events, alone or after another song.
